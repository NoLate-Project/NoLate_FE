# 경로 이탈 후 자동 재탐색 계약

## 현재 코드에서 확인한 경계

- iOS native는 연속 GPS로 경로 이탈을 판정하고, 그동안 경로 바와 Live Activity의 경로상 위치를 숨긴다. 지도에는 별도의 신선한 기기 위치 점만 표시한다.
- 앱의 일반 대중교통 검색은 ODsay `maasRP`를 사용한다. BE의 기존 `/api/routes/transit`는 TMAP 형식의 공급자이므로 새 안내 경로의 근거로 사용하지 않는다.
- `prepare-saved`는 서버에 저장된 개인 경로의 지문, 버전, 도보 형상과 공식 버스·지하철 대응을 검증한 뒤 세션을 만든다. 활성 세션은 이 경로에 묶여 있다. 화면의 경로만 교체하면 native, 서버, Live Activity가 서로 다른 경로를 가리키게 된다.

## 교체 트랜잭션

1. native가 `ACTIVE` 세션에서 경로 이탈을 연속 확인한다. 정확도와 관측 시각이 충분하지 않거나 승차가 확인된 동안에는 자동 재탐색을 요청하지 않는다.
2. 앱은 기존 세션 ID·세대·경로 버전·다이제스트와 신선한 기기 위치를 보낸다. 서버는 세션 소유자와 로그인 세대, 저장 경로 지문, 목적지, 상태를 다시 확인한다. 목적지는 클라이언트 요청에서 받지 않는다.
3. 서버의 ODsay 전용 조회가 현재 위치부터 원래 목적지까지의 경로 후보를 가져온다. 후보의 공급자·형상·정류장 순서·운행 가능성을 검증하고 짧은 유효기간의 서버 소유 후보 ID를 발급한다. 키나 원시 공급자 URL은 응답·로그에 포함하지 않는다.
4. 서버는 선택한 후보의 두 도보 구간과 버스/지하철 공식 대응을 증명한다. 검증되지 않은 후보는 안내 경로가 될 수 없다.
5. 서버가 기존 세션을 종료하고 새 세션·증가한 세대/버전·후보 다이제스트를 한 트랜잭션에서 확정한다. 개인 일정의 저장 경로는 변경하지 않는다. 이미 처리된 출발 이벤트를 다시 전송하거나 출발 알림을 되살리지 않는다.
6. 앱이 서버 영수증과 정확히 같은 새 경로를 native에 원자적으로 설치한다. native 체크포인트·지도·상세·Live Activity가 새 버전을 함께 사용하며, 교체 중에는 예전 경로의 진행 마커를 표시하지 않는다. 앱 재시작 시 서버 영수증을 다시 대조한다.
7. 어느 단계든 실패하면 기존 세션은 `경로 확인 중`으로 남고 확정 안내를 내지 않는다. 재시도는 요청 ID로 멱등 처리하며 반복 위치 조회와 공급자 호출에 제한을 둔다.

## 완료 판정

- 독립 Release 시뮬레이터에서 저장된 실제 ODsay 경로로 출발한 뒤 경로 이탈 GPS를 주입하면, 버튼 없이 새 ODsay 경로가 검색·검증·확정되고 지도·상세·잠금 Live Activity가 같은 새 버전으로 전환된다.
- 앱을 전환 전후에 강제 종료해도 서버와 native가 같은 버전으로 복원되며, 오래된 APNs/관측/출발 영수증은 새 세션을 바꾸지 못한다.
- 실제 GPS와 APNs 전달은 실기기에서 별도로 검증한다.

현재 제품 구현은 1단계의 이탈 판정·지도 위치 표시까지다. BE `feature/journey-reroute`
브랜치에는 2~3단계의 후보 조회 경계가 추가됐다. `ACTIVE` 세션과 저장 경로 지문을
재확인하고, 서버 소유 목적지로 ODsay 원본 형상 후보만 최대 3개 조회한다. 기본
스위치는 `OFF`이고 결과는 새 안내 경로로 확정되지 않는다. 조회 정책·인증 HTTP
테스트는 통과했다. 2026-11-19 독립 Release 시뮬레이터에서 저장된 실제 ODsay
1711 경로로 출발한 뒤 도보·정류장 대기·경로 이탈·복귀 GPS를 재생했다. 제품 E2E가
통과했고, 격리 H2 서버의 실제 ODsay 후보 조회 HTTP 2건이 모두 200을 반환했다.
서버 응답은 비어 있지 않은 `pathType=2` 후보만 허용한다. 이 시험은 후보 조회
연결을 증명하며, 후보 선택·공식 재검증·새 버전으로의 원자적 교체 및 Activity
전환은 아직 수행하지 않았다. 개인 일정의 저장 경로를 우회하거나 변경하지 않는다.

2026-11-19 후보 소유권 후속: 서버는 반환할 ODsay 후보마다 임의 ID를 발급하고
최대 2분 동안 사용자·로그인 세대·일정·활성 세션·경로 세대/버전/다이제스트에
묶는다. 이후 후보 조회자는 같은 활성 세션을 다시 검증해야 서버에 보관된 원본
후보를 받을 수 있다. FE는 ID 누락·형식 오류·중복을 거부한다. 이 ID는 새 경로
확정 영수증이 아니며, 현재 지도·native·Live Activity의 경로를 바꾸지 않는다.
격리 Release 제품 E2E에서 실제 저장된 ODsay 1711 경로를 출발한 뒤
시뮬레이터 GPS로 이탈·복귀했다. 최종 실행은 XCUITest 1건 통과·실패 0건,
격리 서버 후보 조회 2건 HTTP 200, 두 응답 모두 후보 ID 포함이었다
(`/private/tmp/nolate-reroute-candidate-diagnostic-e2e-20261119/result.xcresult`).
첫 실행은 격리 서버의 컴파일 산출물을 시험 도중 갱신해 후보 HTTP가 500이었고,
서버와 산출물을 고정한 재실행에서 위 결과를 얻었다. 첫 500의 세부 예외는
로그에 남지 않아 산출물 갱신을 확정 원인으로 단정하지 않는다.

같은 날 BE 후보 필터에 승차 구간의 노선 형상·정차 목록·좌표 검증을 추가했다.
변경된 서버로 독립 Release 시뮬레이터 E2E를 재실행해 출발·정류장 대기·이탈·복귀가
통과했고, 이탈 GPS 뒤 실제 ODsay 후보 응답 1건이 HTTP 200으로 확인됐다.

실제 ODsay 재탐색 응답 17개는 모두 앱의 경로 옵션과 `ROUTING_RESPONSE` 입력으로
변환됐다. 처음 5개 후보의 승차 구간은 노선 형상과 정차 목록을 가졌지만, 모든 도보
구간의 `geometryInputComplete`는 `false`였다. 따라서 후보 원본만으로 native 안내를
다시 시작할 수 없다. 선택 후보에 대해 현재 위치·환승·목적지 사이의 도보 형상을
새로 확보하고 서버가 소유한 후보와 결합한 다음 공식 승차 증거를 재검증해야 한다.
기존 저장 경로의 도보 스냅샷은 새 후보의 증거로 재사용하지 않는다.

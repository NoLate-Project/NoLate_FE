# P2-1 첫 버스 정류장 접근·대기·탑승 후보 검증

작성일: 2026-10-04 (Asia/Seoul). FE·BE `feature/transit-guidance-v1`.

문서 상태: P2-1 구현·자동 테스트·독립 시뮬레이터 위치 E2E를 완료했다.
합성 위치로 첫 버스 접근·대기·미확정 후보를 검증한 체크포인트이며, P2 전체 또는 실제 버스 내비게이션 완료가 아니다.

## 구현 범위와 실행 제한

P1-3 자동 출발 세션에 첫 버스 구간의 별도 위치 관측 코어를 연결했다. 기존 첫 도보에서 자동 출발이
감지된 이후, 위치 증거로 `WALKING_TO_STOP`, `APPROACHING_STOP`, `WAITING`, `BOARDING_CANDIDATE`를
관측한다. 자료가 부족하거나 위치를 신뢰할 수 없으면 `UNAVAILABLE` 또는 불확실 품질을 표시한다.
`RIDING`으로의 전이나 탑승 완료 사건은 만들지 않으며 `boardingConfirmed`는 항상 `false`다.

- 네이티브 대상은 첫 도보 `leg 0` 바로 다음의 BUS `leg 1`이다. 버스 형상·원본 정류장 순서·명시 방면과
  도보 끝/승차 정류장 연결성을 검사한다. 두 번째 버스, 지하철 이후 버스와 환승은 아직 범위가 아니다.
- 공급자 route ID 또는 차량 ID가 없어도 검증된 형상에서 접근·대기·미확정 후보를 관측할 수 있다.
  이는 같은 도로의 다른 버스·자동차와 구별했거나 특정 버스 탑승을 확인했다는 뜻이 아니다.
- 기존 Debug iOS simulator + 진단 opt-in 제한을 유지한다. 실기기·Release는 시작을 거부하고,
  운영 자동 길안내는 비활성 상태다. 사용자 요청대로 현재 검증 범위는 시뮬레이터만이다.
- 실제 선택 경로의 첫 대중교통 구간이 BUS이면 개발용 P2-1 카드를 표시하되 `LOCAL_ONLY`를 유지한다.
  일정 저장·사용자 서버 준비/출발·알람 변경을 하지 않는다. 지하철이 먼저인 경로는 기존 P1-3 카드다.
- `/internal/journey-bus`는 `SYNTHETIC_FIXTURE`를 유지하는 합성 경로와 `SANDBOX`만 사용한다.
  준비·동의·복구·종료는 시험 제어다. 출발·탑승·다음 단계 버튼이나 단계 강제 입력은 없다.
- 화면 종료와 감지 종료를 분리한다. 기존 P1-3 최대 10분 세션·명시 복구·정지·로그아웃 경계를 유지한다.

| 위치 정확도·시각 | 수평 오차 최대 25m, 나이 최대 15초, 미래 시각 최대 2초 |

대기 없이 정류장을 통과하거나 단순히 빠르게 이동한 것만으로 후보를 만들지 않는다. 후보 조건을
만족해도 차량·노선 매칭 전이므로 탑승은 미확정이다. 낮은 정확도, stale, 시간 역전, 위치 점프,
경로 이탈·역방향 입력은 근거 누적을 초기화하고 거리를 숨긴다. 더 강한 상태로 추측하지 않는다.

복구는 저장된 WAITING/탑승 후보를 그대로 현재 판단으로 재사용하지 않는다. 대기·속도·후보 근거와
거리들을 초기화하고 `RESTORED_NEEDS_FRESH_LOCATION`으로 새 위치를 요구한다. P1-3 출발 사건과
ACK 복구는 별개 계약이다. 종료·만료 이후 입력은 버스 관측을 다시 활성화하지 않는다.

## 화면과 합성 입력

첫 도보의 진행/품질과 버스 구간의 진행/품질을 분리했다. 버스 구간을 이동하면서 첫 도보 끝을
벗어나면 첫 도보가 `OFF_ROUTE`/`UNCERTAIN`이어도 버스 코어는 `GOOD`일 수 있다. 이것을 전체 안내
실패 또는 전체 위치 신뢰로 통합하지 않는다. 버스 카드에는 단계·품질·사유·승차 정류장까지 거리·
버스 형상상 진행·후보 근거 수와 **탑승 미확정 · 차량/노선 매칭 필요**를 표시한다.

`UNCERTAIN`/`UNAVAILABLE`이면 예전 단계가 남아 있더라도 현재 단계로 확정하지 않고 거리도 숨긴다.
버스 형상 불량과 첫 도보 출발 준비 가능 여부도 별도다. 버스만 불량인 경로의 첫 도보 감지는
준비될 수 있지만 버스 관측은 사용 불가여야 한다.

| Fixture ID | 입력 의도 |
| --- | --- |
| `first-bus-valid` | P1-2 `direct-provider-shape`를 독립 복사. 첫 도보 약 132m + 버스 약 881m, 원본 합성 출처 유지 |
| `invalid-bus-middle-coordinate` | 첫 도보와 끝점·정류장 순서를 유지하고 버스 중간 좌표만 위도 95로 변경. 오류 점을 제거/보정하지 않음 |
| `bus-backtracking-shape` | 버스 중간에 역방향 구간 추가. 첫 도보·버스 끝점·정류장 순서는 유지 |

세 입력 모두 실제 노선/차량 ID를 만들어 넣지 않는다. 기존 P1-2 fixture는 수정하지 않았다.

## 서버 관측 어댑터와 동기화의 경계

BE에는 기존 도착 DTO를 받는 순수 `JourneyTransitObservationAdapter`를 추가했다. 원천 갱신 시각과
수신 시각을 구분하고, 만료·미래·예측시각·방면 근거를 검사한다. TAGO의 접근 정류장 수는
`incomingVehicleStopsAway`일 뿐 사용자의 하차까지 남은 정류장 수로 바꾸지 않는다.

어댑터는 공급자 fetch, controller/Spring wiring, 앱 Runtime·UI, 음성/푸시에 연결하지 않았다.
`providerRouteId`, `vehicleId`, `remainingStopsToAlight`는 `null`이며 탑승 확정·차량 추적·안내 발화는
항상 비활성이다. 시간상 신선한 도착정보도 특정 승차 차량을 매칭했다는 증거가 아니다.
상세 계약과 테스트는 [BE P2-1 기록](../../NoLate_BE/docs/schedule/journey-engine-p2-1-transit-observation.md)을 따른다.

SANDBOX는 기존 `127.0.0.1:15543` 준비/출발 HTTP 계약을 재사용한다. 하네스는 실제 controller/service/domain을
호출하지만 사용자·repository·출발/알람 side effect는 fixture/테스트 대역이다. 버스 단계 자체를
운영 서버나 실제 사용자 일정에 기록하지 않으며, 기존 출발 receipt/ACK를 탑승 확정으로 해석하지 않는다.

### 검증 중 발견한 문제

1. 종료 기록은 tombstone으로 저장되는데, 재실행한 Store의 `canRestore`가 파일 존재만 확인하여
   종료한 시험도 복구 가능으로 표시했다. 실제 bounded record를 검사하여 정상 envelope만 복구
   가능으로 표시하도록 수정했다. tombstone은 삭제하지 않는다.
2. 매 위치 입력마다 정확도 오차를 빼면 1Hz 입력에서 이동 속도를 계속 과소 평가할 수 있었다.
   최소 4초의 독립 관측 창으로 속도 근거를 모으도록 보강했다.
3. 초기 통합 시험에서 WAITING 이후 1Hz·10m 이동이 후보가 되지 않고 WALKING_TO_STOP으로
   돌아왔다([수정 전 관측](evidence/journey-p2-1-20261004/06-candidate-first-attempt-not-detected.png)).
   정확도 20m인 단위 입력에서 동일 증상을 재현했고, 속도 상·하한을 구분해 최대 12초까지 추가 관측을
   받도록 보강했다. 최초 화면 시험에는 정확도를 기록하지 않아 그 실패의 원인이 같았다고 단정하지 않는다.
   최종 화면에서는 5m를 확인했고, 끊기지 않는 연속 입력으로 후보 생성을 재검증했다. 20/25m 정확도의
   10m/s 입력은 각각 약 23/29초에 후보가 되는 단위 회귀도 통과했다. 최초 실패는 성공 증거가 아니다.
4. 후보 생성 후에는 속도 누적 창의 timeout이 다시 후보를 지우지 않게 했다. 신선한 위치가 계속되는
   후보 유지와 stale/역방향/이탈 시 해제를 구분하는 회귀를 추가했다.

## 남은 범위

실제 공급자 관측 연결·노선/차량 식별·확정 탑승·하차·한 정류장 전 안내·도착·지하철·환승·재탐색은
미완료다. 음성, 안내 푸시, Live Activity와 실제 APNs 전달·잠금 표시도 이 단계에 연결하거나 검증하지 않았다.
실기기·무음 모드·터널·같은 도로 다른 버스·배터리·현장 정확도는 미검증이다. P2 전체 완료에는 실제
버스 한 경로 완주와 별도의 현장/전달 검증이 필요하다. 합성 시뮬레이터 성공으로 그 게이트를 대신하지 않는다.

`.env`는 열거나 변경하지 않았다. 이 단계에서 커밋·푸시·운영 데이터 변경은 하지 않았다.

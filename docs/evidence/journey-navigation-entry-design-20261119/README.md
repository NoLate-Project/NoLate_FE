화면 녹화에서 검은 화면이나 전체 화면 깜빡임은 보이지 않았다. 시트 스냅은 길안내 확장 시 200ms이고, 지도 따라가기는 최대 420ms로 구현돼 있다. 반면 일정 헤더에서 길안내 헤더로 바뀌는 부분에는 전용 진입 애니메이션이 없어 제목과 상태가 즉시 교체된다. 그 사이 지도 경로도 재표시되어 화면 구성 요소가 한 번에 이어지는 느낌은 약하다. 이는 녹화 프레임과 코드 확인을 합친 판단이며, 실제 사용자가 체감하는 전환 시간의 계측은 아니다.

수정 전 화면은 경로 화면 불투명 처리, Ionicons outline, 접힌 상태의 전 구간 막대와 펼친 상태의 상세 시간 레일 분리라는 디자인 기준을 지켰다. 당시 개선 후보는 다음 다섯 가지였다.

1. 접힌 진입 시트 아래 여백이 큰 편이다. 다음 행동과 막대가 화면 아래쪽에 흩어져 보이므로, 콘텐츠 높이에 맞춰 시트를 줄이거나 첫 행동 정보를 그 공간에 배치할 필요가 있다.
2. `지금 출발`은 길안내 화면으로 들어가지만 실제 GPS 안내에는 `위치 안내 준비`와 동의·시작 단계가 더 필요하다. 처음 사용할 때 필요한 설정은 유지하되, `안내 준비` 상태와 다음 동작을 더 직접적으로 설명해야 한다.
3. 펼친 안내 중 시트에서는 `위치 안내 종료`가 가장 강한 파란 버튼이다. 버스 탑승 화면에서도 이 버튼 아래에 저장 경로와 시간 레일이 이어져, 사용자가 요청한 **경로 막대 위의 현재 위치**를 스크롤 없이 확인하기 어렵다. 현재 단계와 진행 위치를 먼저 보이게 하고 종료는 보조 동작으로 낮추는 것이 화면 목적에 맞다.
4. `지금 출발` 직후에도 주요 문구는 `출발 전`이고, 지도에 현재 위치 마커가 아직 없다. 위치 권한·센서 준비 중인 상태를 명확히 표현하고, 준비 완료 시 현재 위치와 첫 이동 지점을 한 장면에서 연결해야 한다. 실제 위치가 검증되지 않은 동안 마커를 임의로 그려서는 안 된다.
5. 안내 중 버스 제공자 응답이 잠깐 비면 `마지막 확인 · 1711`과 재확인 문구로 바뀌고 위치 마커를 숨긴다. 정확성 보호는 적절하지만, 경로 막대에서도 현재 위치가 일시적으로 확인 불가함을 표현해야 사용자가 지도와 시트를 같은 상태로 이해한다.

## 적용한 화면 수정

이 문서의 `01`–`06` 이미지는 수정 전 화면이다. 이후 네이티브 iOS 앱의 기존 경로 시트를 유지하면서 안내 중 현재 단계와 경로 막대를 **접힌 시트 안에 함께 배치**했다. 상단은 길안내 상태만 표시하고, 펼친 시트에서는 현재 단계 다음에 시간 레일·실시간 도착·정류장 목록을 계속 볼 수 있다. 실제 위치가 검증되기 전에는 경로 막대의 현재 위치 마커를 표시하지 않는다.

진입 헤더와 현재 단계 전환에 짧은 페이드를 넣고 시스템의 동작 줄이기 설정을 따른다. 안내 종료는 작은 보조 동작으로 낮췄다. 별도의 수동 `실제 도착/도착 기록` 카드와 그 입력 컴포넌트는 일정 상세 화면에서 제거했다. 위치 안내의 자동 도착 판정 및 서버의 기존 기록 데이터는 이번 디자인 수정 범위에서 변경하지 않았다.

Figma 파일은 확인했지만 이번 세션의 Figma 도구 호출 한도에 걸려 편집 가능한 제안은 만들지 못했다. 아래의 검증 결과는 **네이티브 Release 빌드와 독립 시뮬레이터**에 관한 것이며, 실기기 GPS·잠금 화면 APNs·음성 출력 검증은 포함하지 않는다.

## 도착 후 화면과 상태 소유권 보강

자동 도착 직후 지도가 전체 경로로 다시 맞춰지던 동작을 수정했다. 현재 일정의 `DESTINATION_ARRIVED`만 목적지에 한 번 초점을 맞추고 시트를 접는다. 이후 전체 경로를 보거나 지도를 직접 살펴보는 동작은 다시 끌어당기지 않는다. 안내 전의 일회성 위치 조회는 시작·종료 경계를 넘어 되살아나지 않으며, 종료 후 `내 위치`를 직접 누르면 새 위치를 조회할 수 있다.

전역 native 스냅샷에 다른 일정의 종료가 남아 있어도 현재 일정의 도착으로 처리하지 않도록, 현재 바인딩 또는 이 화면에서 확인한 같은 계정·일정·경로·세션의 소유권을 확인한다. 도착/종료/만료 및 검증된 종료 Activity 재진입에서는 `위치 안내 준비`를 숨긴다. 시트 안에 이미 있는 저장 경로를 다시 여는 큰 버튼도 제거했다.

첫 목적지 초점 E2E는 통과했지만 스크린샷에 준비 버튼이 남아 있어 완료 증거로 닫지 않았다. 해당 조건을 고친 새 Release 앱의 전체 경로 E2E를 다시 실행했고, 자동 출발부터 도착까지 **1건 통과·0건 실패**했다. [최신 도착 화면](14-arrived-destination-focus.png)에서 목적지 핀, 접힌 경로 막대, 실시간 마커 부재 및 준비/중복 버튼 부재를 직접 확인했다. 결과 번들은 `/private/tmp/nolate-navigation-finished-ui-e2e-20261119/result.xcresult`다. 관련 Jest 73개·TypeScript 검사·iOS Release 빌드도 통과했다. 이 실행 역시 주입 GPS와 독립 시험 차량이며 실제 APNs·실기기 GPS 검증은 아니다.

## 제공한 네이버 지도 화면을 반영한 후속 수정

사용자가 제공한 대중교통 안내 화면(사진 5–7)의 지도·상단 상태·하단 경로 시트 구성을 기준으로 iOS 구현을 다듬었다. 자차 안내 화면(사진 1–4)은 다음 행동을 먼저 읽게 하는 정보 순서의 참고 자료로 사용했다. 이번 변경 대상은 기존 대중교통 화면이다. Figma는 앞서 확인한 MCP 사용 한도로 편집하지 못했으며, 새 브라우저 목업이나 시험용 앱 화면을 만들지 않았다.

- 지도 위를 덮던 전폭 상단 헤더를 뒤로 가기·안내 상태·저장 경로 요약으로 줄였다. 모두 불투명한 표면이다.
- 상단 시간은 저장 경로의 전체 예정 시간임을 `예정 20분`처럼 표시하고 환승 횟수를 함께 보여 준다. 실시간 남은 시간이나 도착 예정으로 해석하지 않는다.
- 접힌 시트의 현재 단계와 다음 행동을 작은 교통수단 아이콘 옆에 배치했다. 전체 경로 막대에는 승차 구간 아이콘을 넣고 기존 검증된 현재 위치 마커를 유지했다. 일반 글자 크기의 5구간 이하 경로에 구간 아이콘을 적용하며, 큰 글자에서는 기존 읽기 쉬운 배치로 돌아간다.
- 펼친 시트는 기존 시간 레일·현재 구간 강조·승차 시각·실시간 도착 정보·정류장 목록을 유지한다. 접힌 경로 막대는 펼쳤을 때 중복 표시하지 않는다. 수동 도착 기록 UI 제거도 유지한다.

## 지금 출발에서 첫 도보까지

저장한 대중교통 일정에서 **지금 출발**을 한 번 누르면 안내 지도가 열린다. 첫 위치 권한 요청은 iOS에서 처리한다. 음성·알림 설정은 출발 버튼 옆에서 열 수 있다. 실제 안내를 시작한 두 차례의 독립 Release 실행 중 첫 실행에서 경로 지도와 출발 버튼을 캡처했다. [출발 전 저장 일정](21-one-tap-departure.png)

후속 실행에서 승객의 위치를 서울역 인근 출발점에 고정했다. 지도는 해당 위치에 맞춰 28도로 기울었고, 시트에 `서울역까지 걷기 · 첫 구간 도보 약 330m`가 표시됐다. 330m는 안내에 사용하는 보행 경로 형상의 전체 길이다. 정지 중에는 상태가 `출발 대기`였다. 보도를 따라 움직이자 상태가 `안내 중`으로 바뀌고 모퉁이를 돌 때 파란 화살표가 남쪽에서 동쪽으로 돌아갔다. 열차 대기 중에는 다시 평면 지도와 위치 점이 표시됐다. [출발점](22-first-walk-at-origin.png) · [모퉁이를 돈 뒤](23-walking-after-turn.png)

iPhone 17 Pro의 iOS 27.0 독립 시뮬레이터에서 1.3.0 (58) Release로 이 흐름을 4분 47초에 통과했다. 시험용 계정에 저장한 경로와 시뮬레이터 위치를 사용했다. 같은 작업의 앞선 빌드에서는 설정 진입, 첫 열차의 한국어 발화 시작·완료, 두 번째 열차의 iOS 로컬 알림으로 같은 일정에 복귀해 안내 종료까지 7분 52초에 통과했다. 최종 타입 검사와 Jest 4,121건이 통과했고 Swift는 453건 중 450건 통과, 3건 건너뜀이다. 실외 GPS와 기기를 제자리에서 돌릴 때의 나침반 반응은 실기기에서 확인할 항목이다.

## 하단 경로 바와 길안내 옵션

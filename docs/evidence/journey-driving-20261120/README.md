# 서울역에서 세종문화회관까지 자차 길안내

서울역에서 세종문화회관까지 TMAP 자동차 경로 API가 반환한 2,571m 경로를 사용했다. NoLate의 경로 파서로 처리해 시험 계정에 자차 일정으로 저장했다. 일반 일정 조회 API로 되읽은 경로에는 원본과 같은 안내 단계 9개와 경로 좌표 105개가 남았다.

iPhone 독립 시뮬레이터의 다크 모드에서 일반 일정 상세의 **지금 출발**로 안내를 열었다. 이동은 해당 도로를 따라 Core Location에 새 좌표를 주입했다. 좌회전, 오른쪽 방향, 왼쪽 방향 순서와 안내 문구는 저장한 TMAP 원본에서 가져왔다.

## 시험 결과

iOS 27.0 독립 시뮬레이터에서 **Release 1.3.0 (58)** 의 일반 주행 E2E 1건이 294.705초에 통과했다. 시작 전 서버의 본인 출발 시각은 비어 있었고, 실제 이동 좌표가 확인된 뒤 시각이 기록됐다. 목적지에서 감속해 머문 뒤 도착 안내가 표시됐고, 종료를 누르면 저장 일정 상세로 돌아왔다.

같은 빌드에서 실제 위치 권한 철회 E2E 1건도 186.650초에 통과했다. 잠금 카드가 두 번째 회전을 지난 뒤 NoLate의 시뮬레이터 위치 권한을 철회했다. 권한 철회 약 64초 뒤 잠금 카드에는 목적지와 ‘현재 위치를 확인하는 중’이 남았고 거리, 다음 회전, ETA가 사라졌다. 캡처 아래에는 iOS의 실시간 현황 계속 허용 창도 보인다. 64초는 이 시험에서 잠금 화면이 갱신된 관측값이다. [위치 권한 철회 후 잠금 화면](10-location-access-revoked.png)

## 확인 방법

- `e2e/ios/CarNavigationProductTests.swift`의 `testSavedDrivingRouteFollowsLocationThroughTurns`는 실제 경로에서 안내 문구와 거리가 바뀌는지 확인한다. `--lock-moving` 실행은 독립 창이 잠겨 있는 동안 다음 회전을 지나고, 잠금 카드의 목적지를 직접 눌러 같은 주행으로 돌아온다.
- `testLockedDrivingRouteWithdrawsGuidanceWhenLocationIsRevoked`는 시험 기기에서 NoLate의 위치 권한만 철회한 뒤 잠금 카드의 정보가 어떻게 바뀌는지 확인한다. 드라이버가 시험 종료 시 위치 권한과 테마를 복원한다.
- 두 시험은 `e2e/ios/run-journey-car.py`로 실행한다. 드라이버는 시험 서버의 JVM, 본인 일정, 서명된 시뮬레이터 앱과 지정 기기를 먼저 확인한다. 실기기 GPS의 수신 품질은 별도 실주행 검증 대상이다.


## 입체 주행 지도와 현재 위치의 이동 방향

2026-11-20, iOS 27.0의 독립 iPhone 시뮬레이터에서 저장 일정의 일반 길안내 화면을 확인했다. 자차와 대중교통 시험 모두 격리 서버와 시뮬레이터 Core Location을 사용했다.

- **자차** — 서울역에서 세종문화회관까지 이동했다. 남쪽, 북쪽, 서쪽 주행에서 마커의 접근성 방향이 실제 이동 구간과 일치했고, SDK에서 되읽은 지도 기울기는 세 구간 모두 40도였다. 지도에서 차량은 화면 중심보다 아래에 있고 도로의 진행 방향이 위로 향했다. 지도를 손으로 밀고 현재 위치로 복귀한 뒤 이탈·재진입·도착까지 통과했다. 최종 주행 E2E는 244.346초였다. [남쪽 주행](11-driving-south.png) · [북쪽 주행](12-driving-north.png) · [서쪽 주행](13-driving-west.png)
- **대중교통** — 서울역까지 걷는 동안 이동 방향이 위치 마커에 나타났고, 승강장에서 열차를 기다리자 방향 화살표가 사라졌다. E2E는 279.778초였다. 이 시험은 자차 화면에 SDK 기울기 접근성 값을 추가하기 직전의 Release에서 실행했다. [역까지 도보](14-transit-walking-heading.png) · [승강장 대기](15-transit-platform.png)
- **재현** — 자차는 기존 `e2e/ios/run-journey-car.py`의 일반 주행, 대중교통은 `e2e/ios/run-journey-subway-transfer.py`의 `--verify-walking-heading`으로 실행한다. 자차 시험에서는 Core Location 방향을 미상으로 두고 연속 좌표로 계산한 방향까지 검증했다. 최종 타입 검사와 Jest 4,094건이 통과했다.

## 교차로에서 보이는 회전 방향

주행 중 다음 회전까지 180m 이내로 접근하면 실제 도로 경로 위에 흰색 화살표가 나타난다. 차량의 현재 방향은 파란 마커가, 교차로에서 앞으로 갈 방향은 흰색 화살표가 보여 준다. 연속된 회전에서는 화살표가 이웃한 교차로까지 넘어가지 않도록 길이를 제한했다. 회전 유형은 [TMAP 자동차 경로 응답 명세](https://tmap-skopenapi.readme.io/reference/경로안내-샘플예제)를 기준으로 판별한다.

같은 출발지와 목적지를 저장한 독립 iPhone 17 Pro 시뮬레이터에서 Release 주행 E2E가 231.046초에 통과했다. 저장 일정 진입부터 회전 전환, 경로 이탈과 복귀, 도착까지 자동으로 확인했다. 캡처를 대조해 한강대로 좌회전 61m 전과 새문안로5길 우회전 118m 전 모두 배너의 방향과 지도 위 화살표의 방향이 일치하는 것을 확인했다. [한강대로 좌회전](16-junction-left.png) · [다음 오른쪽 방향](17-junction-right.png) · [경로 이탈](18-junction-off-route.png) · [새문안로5길 우회전](19-junction-road-turn.png)

같은 교차로를 다른 방향으로 다시 지나는 경로, 가까운 두 회전, 도착 안내에서의 화살표 처리도 단위 테스트에 포함했다. Jest 378개 스위트의 4,101건이 통과했다. 위치 입력은 시뮬레이터에서 재생했다.

## 주행 중 자동 경로 재탐색

서울역 인근에서 저장된 한강대로 경로의 동쪽으로 약 80m 이탈했다. 정확도 4m의 Core Location 입력을 계속 보내고, 새 경로 버튼을 누르지 않았다. iOS 앱은 이탈이 12초 이상 지속되자 그 위치에서 세종문화회관까지 TMAP에 자동차 경로를 다시 요청했다. 독립 시뮬레이터에는 전체 주행과 같은 Release 앱을 설치했고, 서버에는 별도의 시험 일정을 저장했다.

| 관측 시점 | 제품 화면 |
| --- | --- |
| 경로 밖으로 이동 | 현재 차량 마커와 지도가 남고 기존 경로는 회색으로 바뀌었다. 이전 도로의 회전과 ETA는 사라졌다. [이탈 화면](20-detour.png) |
| 앱이 새 경로를 받음 | 후암로60길까지 8m, 4시 방향 우회전이 표시됐다. [새 경로 첫 회전](21-rerouted.png) |
| 새 도로를 따라 첫 교차로를 통과 | 다음 우회전까지 55m, 진입할 도로는 한강대로였다. 차량의 방향 마커와 교차로 화살표를 함께 확인했다. [다음 회전](22-rerouted-next-turn.png) |
| 목적지에 도착 | 세종문화회관 도착 후 안내를 종료하고 원래 일정으로 복귀했다. [도착 화면](23-rerouted-arrival.png) |

첫 실행에서 재탐색 직후 출발점이 다음 행동으로 선택돼 배너에 0m가 남는 현상을 재현했다. 출발점은 도로 형상 계산에 유지하고 다음 행동은 첫 실제 회전부터 선택하도록 수정했다. 새 경로의 거리가 출발 좌표에 따라 몇 미터 달라지므로 E2E는 교차로의 회전 방향, 도로 이름, 순서와 최종 도착을 대조한다.

자동 재탐색 E2E는 247.418초에 통과했다. 드라이버는 이탈 지점에서 목적지까지 별도로 받아 둔 TMAP 응답을 `run-journey-car.py --reroute-response FILE`로 읽고 위치 재생과 예상 회전 순서를 구성한다. 앱은 일반 경로 요청으로 응답을 받는다. 통신 실패 후 현재 위치에서 재시도, 응답 지연 중 기존 도로 복귀, 다른 목적지의 응답 배제는 훅 단위 테스트로 확인했다. 최종 타입 검사와 Jest 378개 스위트 4,106건이 통과했다.

같은 Release에서 짧은 이탈 뒤 기존 도로로 복귀하는 시나리오도 확인했다. 기존 설치 재사용 시도에서 XCTest가 일정 딥링크의 접근성 응답을 기다리다가 시간 초과했다. 당시 캡처에는 일정 상세와 ‘지금 출발’이 표시돼 있었다. 독립 기기에 같은 빌드를 새로 설치한 뒤 일반 주행 E2E가 226.121초에 통과했다. 두 성공 시나리오 모두 서버에서 출발 시각이 기록됐고, 저장된 일정의 원래 경로는 그대로였다.

## 자차 음성 안내와 음소거

자차 안내에서 처음에는 기기에 저장된 길안내 음성·알림 설정을 따르고, 스피커 버튼을 누른 뒤부터는 사용자가 고른 자차 음성 설정을 다음 주행에도 적용한다. 기존 선택이 없는 기기의 첫 주행은 음소거다. 짧은 회전 안내에는 진입할 도로 이름을 포함하고, 10m 이내의 회전은 ‘잠시 후’로 읽는다.

iOS 27.0 독립 iPhone 17 Pro 시뮬레이터의 Release 앱에서 서울역 → 세종문화회관 저장 일정으로 시험했다. 서울역 첫 회전에서 음성을 켜고, 다음 회전 전에 끈 뒤, 다시 켰다. 앱 프로세스를 종료하고 새로 실행해 같은 일정의 안내로 들어갔을 때도 켜짐 상태와 발화를 확인했다. 마지막에는 음소거한 뒤 안내를 닫고 다시 열어 같은 경로를 이동했다. [음성 켜짐](24-voice-enabled.png) · [다음 회전 음소거](25-voice-muted.png) · [재실행 후 음성 복원](26-voice-restored.png)

| 시험 구간 | 한국어 발화 시작 | 발화 완료 |
| --- | ---: | ---: |
| 첫 진입 · 음소거 | 0 | 0 |
| 첫 회전 · 켜짐 | 1 | 1 |

시험 드라이버의 `--voice` 옵션은 지정 시뮬레이터의 NoLate 음성 합성기 콜백을 수집해 각 조작 시간과 대조한다. 재실행 전후 앱 프로세스가 서로 다른지도 검사한다. E2E는 177.942초에 통과했다. 타입 검사와 Jest 4,106건이 통과했고, Swift 패키지는 447건 통과, 별도 입력이 필요한 3건을 건너뛰었다. [발화 검증값](driving-speech-proof.json) · [Apple 음성 합성기 콜백](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizerdelegate/speechsynthesizer(_:didstart:))

자차 음성은 iOS의 ambient 오디오 세션을 사용한다. 실기기의 무음 스위치, 차량 스피커와 Bluetooth에서 들리는 음량은 실주행에서 확인할 항목이다. [Apple 오디오 세션 문서](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/ambient)

## 도보 원근 지도와 현재 위치 방향

같은 iPhone 17 Pro 독립 시뮬레이터의 iOS 27.0 Release 앱에서 저장된 대중교통 일정으로 출발했다. 서울역까지 걸어가는 동안 지도 SDK에서 읽은 기울기는 28도였다. 보도를 따라 모퉁이를 돌자 파란 화살표가 남동쪽에서 동쪽으로 돌아갔고, 경로 시트를 펼쳐도 마커는 지도 안에 보였다. 서울역에 도착해 열차를 기다릴 때는 지도가 0도로 돌아오고 위치는 파란 점으로 표시됐다. 대중교통 E2E 소요 시간은 283.186초였다. [도보 240m](27-walking-perspective.png) · [모퉁이를 돈 뒤 90m](28-walking-turn.png) · [서울역 열차 대기](29-station-overhead.png)

도보 구간에서 이동 방향을 측정하기 전에는 iPhone의 나침반 값이 충분히 정확할 때 기기가 향한 쪽을 표시한다. 최근 이동 방향이 확인되면 그 방향을 우선한다. 나침반 정확도 저하, 유효 시간 경과, 구간 종료 후 늦게 들어오는 센서 값은 단위 테스트로 확인했다. 실제 iPhone을 제자리에서 돌렸을 때의 반응과 실외 GPS 정확도는 실기기 검증 대상이다.

같은 Release로 서울역에서 세종문화회관까지 자차 주행도 재검증했다. 남쪽·북쪽·서쪽 주행에서 지도 기울기는 40도였고 회전, 경로 이탈과 복귀를 거쳐 목적지에 도착했다. 자차 E2E는 244.451초에 통과했다. 타입 검사와 Jest 4,107건도 통과했다. [서쪽 주행 중인 지도](30-driving-perspective.png)

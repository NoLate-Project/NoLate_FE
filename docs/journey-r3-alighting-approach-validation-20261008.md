# R3-1 하차 준비 안내 검증

2026-10-08. FE/BE `feature/transit-guidance-v1`.

## 구현 경계

- 첫 버스 구간만 지원한다. 공식 crosswalk로 admission된 동일 형상과 순서가 검증된 저장 정류장 목록에서 마지막 하차 occurrence 및 그 이전 occurrence를 선택한다. 임의 정류장 이름·`sectOrd`·`lastStnId`로 현재 정류장을 추정하지 않는다.
- 동일 session/generation/revision/digest의 네이티브 RIDING/GOOD/boardingConfirmed와 원래 차량 TTL 안의 위치만 사용한다. 후보·차량 없음·만료·위치 품질 저하에는 하차 안내나 정확한 마커를 만들지 않는다.
- 마지막 전 정류장의 투영 지점보다 25m의 보수적 GPS 여유를 지나야 `ONE_STOP_BEFORE`다. 목표까지의 경로상 잔여 거리+25m가 50m 이하일 때 `NEAR_STOP`이다. 이는 경로 투영 기준이며 실측 정류장 반경 보증이 아니다. 거리는 위로 10m 단위 반올림한다. 시계·예정 ETA로 이동을 계산하지 않는다.
- 상세/Live Activity는 하차 정류장 이름과 ‘다음 정류장 · 약 Xm 앞 · 하차 준비’ 또는 ‘정류장 근처 · 하차 준비’를 표시한다. 마커·현재 행은 여전히 버스 구간이다. 음성·알림 이벤트는 이번 범위가 아니다.
- schemaVersion 3은 RIDING 표시 계약에 `alighting={kind, remainingMeters}`만 추가한다. v1 도보/대기와 v2 단순 버스 이동은 유지한다. 좌표·차량 ID·임의 키·모순된 schema/phase/확정 상태는 거부한다. 서버 수용은 인증된 클라이언트의 표시 보고이며 서버 독립 하차 판정이 아니다.
- 정상/만료 END는 alighting·rideProgress·boardingConfirmed를 제거한다. live 차량/접근 근거는 영속 데이터에서 복구하지 않는다.

## 코드 검사

- Swift 전체 306건 PASS. 새로운 policy의 occurrence·오차 경계·신선도·불확실성·잘못된 형상/노선/정류장 목록과 표시 계약을 포함한다.
- FE 전체 Jest 297 suites / 2,735건 PASS. 이후 내부 설명 문구 변경 관련 7 suites / 228건 PASS. TypeScript PASS.
- BE 여정/교통/Live Activity 관련 53 suites / 385건 PASS, 실패·오류·skip 0. 격리 MySQL Testcontainers 포함. 운영 DB 변경 없음. 무필터 프로젝트 전체 테스트는 실행하지 않았다.
- QA 30건 PASS. iOS 진단 Debug 빌드 PASS. 임시 Info.plist 플래그는 소스에서 원복했고 운영 기본 OFF는 유지한다.

## 독립 시뮬레이터 E2E

대상: `NoLate R2 Session E2E 20261008` / iOS 26.5 / `96AF9A48-4721-4335-B7BF-10B9382B7A30`.
`Show in Device Hub` 툴바가 있는 분리된 창만 조작한다. 다른 기기/내장 미리보기는 조작하지 않는다.
별도 서버 clock의 합성 차량과 `journey-alighting-location-replay.mjs`의 승객 CoreLocation 주입을 사용한다.
실제 공급자·실제 APNs는 OFF이며 엔진 phase 전환 버튼/강제 상태 입력은 없다.

첫 실행에서 근처·체류·만료·종료·콜드 재진입을 확인하고, 한 정류장 전 화면은 관측 시점을 놓쳐 같은 전체 GPS 시나리오를 재실행했다. 두 실행에서 다음을 관측했다.

- 두 번째 실행의 상세 화면에서 ‘합성 정류장 3 · 다음 정류장 · 약 170m 앞 · 하차 준비’와 버스 구간 안의 위치 마커/현재 버스 행을 확인했다. 연속 입력 중 AX의 다음 표본은 160m였다. 잠금 카드에서는 ‘다음 정류장 · 약 30m 앞 · 하차 준비’와 같은 버스 구간 마커를 육안 확인했다. 시간 기반 카운트다운이 아니라 실제 주입된 승객 위치의 경로 투영 잔여 거리다.
- GPS 출발 1회/ACK 이후 차량 동행으로 RIDING/근거 10개가 되었다. 목표 정류장 근처에서 ‘합성 정류장 3 · 정류장 근처 · 하차 준비’가 자동 표시됐다.
- 실제 상세 컴포넌트의 현재 행은 버스 leg 1이며 최종 도보/도착 행에는 현재 위치가 붙지 않았다. 지도 엔진 위치는 합성 목표 좌표 근처였다.
- 독립 잠금 화면에서 같은 정류장/하차 준비 문구와 버스 구간 끝 부근의 파란 위치 마커를 육안 확인했다. 시스템의 ‘항상 허용’ 선택은 바꾸지 않았다.
- 목표에서 계속 차량과 머무르는 동안 하차 완료/최종 도보/도착으로 전환하지 않았다. 두 번째 실행에서도 목표 체류 후 RIDING/근거 14개와 버스 현재 행을 확인했다. 차량 관측을 제거하고 승객 GPS만 25초 유지한 뒤 상세와 잠금 카드 모두 위치 확인 중으로 바뀌고 하차 문구/정확한 마커가 사라졌다.
- 상세의 종료 버튼으로 STOPPED/근거 0/차량 조회 NOT_REQUESTED/서버 종료 대기 0/오류 없음을 확인했다. 다시 잠근 화면에서 카드가 제거됐다.
- GPS 주입 해제 후 앱 terminate/launch·콜드 재진입은 IDLE/출발 0/근거 0/종료 대기 0/남은 기록 없음/시험 동의 해제였다. 탑승·하차 접근 근거를 복구하지 않았다.

창 캡처가 이전 프레임을 반환한 경우 AX와 불일치한 이미지는 합격 근거로 쓰지 않았다. 분리 창 Raise/깨우기/잠금 전환 후 최신 시각·화면을 다시 확인했다. 이 시험은 실제 지도 타일·현장 GPS·실제 APNs·실제 하차 검증이 아니다.

두 번째 전체 replay도 정상 완료했고, 차량 근거 제거 후 UNAVAILABLE/근거 0/위치 확인 중과 종료 후 STOPPED/NOT_REQUESTED/종료 대기 0을 재확인했다. 시험 종료 후 이 시뮬레이터의 GPS 주입을 해제하고 앱을 종료했다. 이번 실행에서 시작한 Metro(8088)와 격리 harness(15544/15545)만 종료했고 listener가 없음을 확인했다. 시험 기기·앱 데이터·기존 파일은 삭제하지 않았다. 진단 Info.plist는 원복, FE/BE diff whitespace 검사 PASS다.

## 다음 게이트

R3 전체 완료가 아니다. 차량–승객 분리 근거와 검증된 마지막 도보 연결이 필요하다. 현재 어댑터는 선택 버스 구간의 근거만 제공하므로, 정류장 근처에서 느려짐/체류/차량 관측 소실만으로 하차를 확정하지 않는다. 후속은 연관 차량의 선택 구간 밖 관측을 안전하게 연결하는 계약과 실제 경로 매핑 재검증, 이후 하차→최종 도보→목적지 체류 reducer다. R5 안내 채널과 R6 지하철·환승도 남아 있다.

이번 실제 서울 API·실제 APNs 호출은 0건이다. 키/토큰 원문·실제 공급자 응답·실제 사용자 GPS를 출력하지 않는다. `.env`·운영 설정·기존 사용자 데이터 변경, 커밋·푸시·배포는 하지 않는다.

# R3-2 동일 차량 출발·승객 분리 근거

2026-10-08. FE/BE `feature/transit-guidance-v1`. R3-2 구현·자동 검사·독립 시뮬레이터 E2E 완료. R3 전체 완료는 아니다.

## 구현 경계

- 기존 선택 구간 뒤의 관측을 모두 버리던 계약을 보완한다. 공식 전체 정류장/형상 매칭으로 하차 occurrence와 바로 다음 동일 방면 occurrence가 유일하고 그 간격이 100~350m일 때만 정류장 조회 범위를 1개 늘린다. 실패하면 기존 선택 구간만 지원한다. 반환 차량도 전체 형상에서 유일한 투영과 확장 상한을 만족해야 한다. 노선 전체로 조회를 넓히거나 도로 구간 순번을 정류장 순번으로 대체하지 않는다.
- 인증된 ride 관측 계약 v2는 binding의 `departureWindowMeters`, 차량의 `positionScope`/`metersPastAlighting`을 추가한다. `AFTER_ALIGHTING`은 차량 위치의 구간 분류일 뿐 사용자가 하차했다는 의미가 아니다. Activity 표시 schema v1/v2/v3는 이번에 바꾸지 않는다. 이전 native 관측 v1은 선택 구간 전용으로 읽으며 하차 후 필드가 섞이면 거부한다.
- 원본 차량 시각·15초 TTL·동일 세션/세대/revision/digest·공식 crosswalk·조회 전후 소유권 검증·11초 client 간격/10초 server cooldown을 유지한다. 추가 polling 요청/좌표 업로드/차량 ID 영속화는 없다. 운영 기본 OFF와 DEBUG 시뮬레이터 범위도 유지한다.
- 네이티브 분리 수집기는 목표 근처의 신선한 RIDING/GOOD/확정 차량 ID로만 시작한다. 승객이 오차 반경을 포함해 목표 50m 안에서 저속이고, 동일 차량이 검증된 다음 구간 75m 이상 진행하며 승객과 오차를 뺀 60m 이상 떨어졌을 때만 관측을 모은다. 서로 다른 원본 시각 3회·12초 이상·차량 전진 40m 이상이 필요하다. 같은 표본 재수신으로 근거나 TTL을 늘리지 않는다.
- 최초 차량 연관 근거는 최대 90초만 유지한다. GPS 불량/목표 이탈/종료에는 제거하며 차량 없음·다른 차량·중복·만료에는 양성 근거를 만들지 않는다. 모든 근거는 메모리 전용이고 재시작 복구하지 않는다.
- 내부 읽기 전용 화면의 `SEPARATION_OBSERVED`는 분리 근거만 뜻한다. 상세/Live Activity에는 최종 도보 마커나 도착을 만들지 않는다. 차량이 떠나 RIDING 근거가 끊기면 제품 화면은 위치 확인 중으로 안전하게 전환한다. 음성/푸시 이벤트도 이번 범위가 아니다.

## 검사 및 독립 시뮬레이터 E2E

- Swift 전체 315건 PASS. 분리 근거 수집·원본 시각 중복/만료·과거 탑승 없음·동일 차량 불일치/중복·좌표 불량·승객이 차량과 계속 이동·종료·identity fence와 v2 admission을 포함한다. 하차 후 구간 관측이 새 탑승 근거로 사용되지 않는 회귀도 포함한다.
- FE 전체 Jest 297 suites / 2,741건 PASS. 최초 신규 테스트가 없는 guidance를 null로 기대해 1건 실패했고 실제 계약인 undefined로 수정 후 전체 재실행했다. 분리 진단은 제품 phase나 차량 ID/이력으로 승격하지 않는 검사를 포함한다. TypeScript PASS.
- BE 여정/교통/Live Activity 관련 53 suites / 389건 PASS, 실패·오류·skip 0. 격리 MySQL Testcontainers 포함. 프로젝트 무필터 전체 합격을 뜻하지 않는다.
- QA 33건 PASS. iOS 진단 Debug 빌드와 최종 코드 재빌드 PASS. 임시 Info.plist는 소스에서 원복했다.

E2E 대상은 기존 분리 창 `NoLate R2 Session E2E 20261008` / iOS 26.5 / `96AF9A48-4721-4335-B7BF-10B9382B7A30`이다. `Show in Device Hub` 툴바가 있는 독립 창만 조작했다. 앱 프로세스의 표시 이름은 Device Hub이지만 내장 preview가 아닌 해당 기기의 분리 창에서 확인했다.
별도 합성 서버 clock으로 차량은 목표 정류장에서 30초 정차한 뒤 출발하고, 승객 CoreLocation 주입은 목표 근처에 계속 머문다. phase/탑승/하차 강제 입력은 하지 않는다. 실제 공급자와 실제 APNs는 OFF다.

관측 결과:

- ARMED/출발 0/분리 0 → 승객 GPS ACTIVE/출발 1/ACK → 차량 없는 WAITING/분리 0 → RIDING/차량 근거 3~8개/분리 0을 확인했다.
- 목표 근처에서 RIDING과 하차 준비를 유지했으며 분리 진단은 `MATCHED_DEPARTING_VEHICLE_REQUIRED / 0개`였다. 동일 시점의 독립 잠금 카드에는 ‘합성 정류장 3 · 정류장 근처 · 하차 준비’와 버스 구간 끝의 마커가 표시됐다. 함께 정차하는 것만으로 분리를 만들지 않았다.
- 승객은 목표에 머무르고 같은 버스만 출발했을 때 `COLLECTING / 1개` → `SEPARATION_OBSERVED / SAME_VEHICLE_DEPARTED_PASSENGER_AT_TARGET / 3개`를 화면에서 확인했다. 기존 RIDING은 UNAVAILABLE로 내려가지만 transport는 `VEHICLE_INPUT_RECEIVED`로 하차 후 관측을 전달했다.
- 실제 상세 컴포넌트와 독립 잠금 카드는 ‘위치 확인 중’을 유지했다. 정확한 현재 위치 마커·최종 도보 현재 행·도착 상태를 만들지 않았다. 분리 근거만으로 하차를 확정하지 않는 경계를 확인했다.
- 이후 차량 입력을 제거하고 승객 GPS만 25초 유지했다. 진단 재확인 시 차량 연결은 `VEHICLE_EVIDENCE_UNAVAILABLE`, 분리는 `UNAVAILABLE / CORRELATION_WINDOW_EXPIRED / 0개`였다. 이 화면은 상관 근거 90초 만료 이후이므로 ‘차량 없음이 즉시 근거를 제거함’의 시간적 E2E 증명으로 쓰지 않는다. 즉시 제거·동일 차량 불일치·계속 탑승 등의 음성 조건은 자동 검사로 검증했다.
- 정상 종료 후 `STOPPED / SESSION_STOPPED / 0개`, 차량 조회 `NOT_REQUESTED`, 서버 종료 대기 0건·오류 없음을 확인했다. 독립 잠금 화면에서 Activity 카드도 사라졌다.
- GPS 주입을 해제하고 앱 terminate/launch 후 다시 진입했다. `IDLE / 출발 0 / 분리 0 / NOT_REQUESTED`, 남은 안내 기록 없음·종료 큐 0·동의 unchecked를 AX와 화면에서 확인했다. 이전 분리 근거는 복구되지 않았다.

시험 중 OS의 실시간 현황 ‘항상 허용’ 권한은 추가로 선택하지 않았다. 시험 종료 후 위치 주입을 해제하고 대상 앱과 이번에 시작한 로컬 Metro/합성 서버만 종료했다. 시뮬레이터·앱 데이터·다른 작업의 서버는 삭제하지 않았다.

## 다음 게이트

R3-3은 이 분리 근거와 검증된 최종 도보 연결·연속 도보 관측을 함께 요구해야 한다. 동일 차량 분리 없이 정차/관측 소실만으로 하차를 확정하지 않고, 목적지 체류 없이 도착을 만들지 않는다. 현재 R3 전체 완료도, 실제 노선/현장 GPS/실제 APNs 검증도 아니다.

이번 `.env`·운영 설정 변경, 커밋·푸시·배포는 하지 않았다. 격리 시험 기기에만 합성 세션을 생성·종료했고 기존 사용자/운영 데이터는 변경하지 않았다. 실제 서울 API/APNs 호출은 0건이며 키·토큰·차량 원문·실제 사용자 GPS는 출력하지 않았다.

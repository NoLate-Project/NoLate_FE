# 제품 상세 음성·알림 설정 연결 — 2026-10-13

실제 `SavedJourneyTrialControls`의 준비 화면에 `JourneyNoticeControls`를 연결했다.
기본 접이식 ‘음성·알림 설정’은 현재 native 선택을 보여준다. 열기/렌더링만으로 권한
요청·FCM 토큰 등록·음성 실행·출발/탑승/단계 전환을 하지 않는다. 권한 요청·앱 설정·
알림만/전경 음성+알림/OFF는 명시적인 별도 동작이다. 기존 내부 시험 화면은 펼친 형태를 유지한다.

선택/권한 요청이 진행 중이면 준비/검사/도보 연결/동의를 잠그며 ref fence로 같은 프레임
중복 탭도 막는다. 실행 중에는 설정 변경을 숨기고 현재 안내 방식을 요약한다. native도
전경·실행 전 조건을 재검사한다. 다른 경로의 세션을 이 화면에서 변경/종료하지 않는다.

음성은 현재 전경에서만 큐에 넣고 무음을 존중한다. 잠금에는 로컬 알림을 사용한다.
잠금 음성·실제 청취·실제 APNs까지 구현/검증됐다는 뜻이 아니다. 내부 진단만 bounded
알림 상태/권한/접수 수/음성 큐를 추가하고 좌표·토큰·provider 원문은 출력하지 않는다.

자동 검사: 최종 FE 전체 **321 suites/3,129 PASS**, TypeScript PASS.
긴 세션 복구 인증 horizon 거절 검사와 권한 상태별 표시 검사를 포함한다. native 변경은 없다.

독립 창 `NoLate Mixed Journey E2E 20261012`에서 새 Metro 번들로 실제 상세 컴포넌트의
접힌 OFF 설정 → 명시적 전경 음성+알림 선택 → 선택 상태 → 준비 후 설정 숨김/채널 요약을
확인했다. 이 과정에서 권한 요청·토큰 등록은 하지 않았다. GPS 재생은 수동 단계 명령 없이
현재 위치 마커, 첫 버스, 환승 후 잠금 다음 버스 대기 1분, 두 번째 버스 하차 준비 60m를
확인했다. 전경 진단의 음성 큐 4는 실제 청취 증거가 아니다. 잠금 Activity는 로컬 갱신이다.

재설치 뒤 OS 알림 권한은 `NOT_DETERMINED_LOCK_UNSUPPORTED_ALERT_UNSUPPORTED`였다.
따라서 알림 접수 0은 결함으로 감추거나 실제 알림 PASS로 바꾸지 않는다. 시험 앱의 알림
허용 여부를 별도로 질의했으며 승인 전 권한창을 누르지 않았다. 기존 채널 요약이 권한과
무관하게 잠금 알림을 보장하는 것처럼 보이는 문구를 수정했다. OFF는 표시하지 않고,
미허용/거절/잠금 OFF/미확인/제한 권한을 구분한다. 완전 허용도 집중 모드 등 OS 정책에
따라 실제 표시가 다를 수 있다고 안내한다. 권한 요청 직후 오래된 미결정 metadata는
잠금 허용으로 승격하지 않고 보수적으로 재확인을 표시한다.

이번 GPS 재생은 exit 0이며, 잠금 카드 제거 뒤 전경에서 **DESTINATION_ARRIVED / STOPPED /
자동 출발 1 / 종료 대기 0 / 알림 접수 0 / 음성 큐 4**를 AX로 확인했다. 마지막 도보의

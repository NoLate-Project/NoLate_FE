# R2-3 버스 이동 상태 → 상세 경로·Live Activity

날짜: 2026-10-08. FE/BE `feature/transit-guidance-v1`.

## 변경

- 네이티브 동행 reducer가 신선한 차량 근거로 확정한 RIDING만 표시한다. 준비·정류장 대기·탑승 후보나 빠른 GPS만으로 버스 이동 마커를 만들지 않는다.
- RIDING 표시 계약은 schemaVersion 2, boardingConfirmed=true, activeLegIndex=1, rideProgress를 사용한다. 첫 도보/대기는 기존 v1/walkProgress를 유지한다. 두 진행률을 섞거나 v1에 RIDING을 끼워 넣는 입력은 거부한다.
- 원본 승객 GPS를 버스 형상에 투영한 진행으로 버스 구간 안의 마커를 움직인다. 예정 시간 비례는 경로 바 구간의 정적 폭일 뿐, 시계로 위치나 전체 여정 완료율을 계산하지 않는다.
- 상세 지도 위치 점·경로 바·현재 목록 행과 Live Activity가 동일한 native projection을 사용한다. 노선명이 검증되면 노선명/‘버스로 이동 중’을 표시하며 퍼센트·근거 없는 다음 정류장/하차/ETA는 표시하지 않는다.
- 동일 차량 fix를 다시 받아도 근거 개수와 원본 차량 TTL을 늘리지 않는다. 그 fix가 아직 유효한 동안의 새 승객 GPS는 반영한다. 차량 또는 위치 근거 만료 시 마커·지도 위치·현재 행과 확정 상태를 숨긴다.
- 서버 UPDATE 계약은 제한된 v2 표시 필드를 받아들이고 좌표·차량 ID·임의 필드는 차단한다. 기존 인증·세션/소유권·revision/digest·TTL·크기·단조 timestamp 검증은 유지한다. 이는 클라이언트 표시 보고 계약이며 서버 자체가 승객 탑승을 독립 확정했다는 뜻은 아니다.
- durable END와 시험 sender END에서 rideProgress와 boardingConfirmed를 제거한다. 앱 재시작 시 차량 동행 근거는 복구하지 않는다.
- 연속 시험 중 정지 관측 구간에서 RIDING 근거 만료가 관측돼 최초 실행은 통과 처리하지 않았다. 서버 cooldown이 차량 요청 승인 시점부터 시작하는데 클라이언트는 선행 binding 요청 시작부터 10초를 세던 경합 가능성을 제거했다. 다음 조회는 완료 후 11초 이후이며 원본 차량 TTL은 늘리지 않는다. 서버의 제한/빈 근거/공급자 실패 상태도 고정된 허용 목록으로 구분한다.
- 시험 replay의 정지 구간은 동일 좌표 반복 대신 ±0.5m의 합성 GPS 흔들림을 사용한다. 새 CLLocation 시각 전달을 유도하기 위한 시험 입력 보완이며, 차량 관측·탑승 상태를 만들거나 실제 GPS 정확성을 증명하지 않는다. 최초 끊김의 단일 원인을 확정한 것은 아니다.

## 독립 창 E2E

대상은 기존 격리 시험 기기 `NoLate R2 Session E2E 20261008` (iOS 26.5),
`96AF9A48-4721-4335-B7BF-10B9382B7A30`다. 다른 시뮬레이터·실기기·사용자 데이터는 조작하지 않는다.
독립 창의 `Show in Device Hub` 툴바를 확인했다. 화면 조작은 이 창에서만 수행한다.

승객 GPS replay와 서버의 별도 시계 기반 합성 차량 흐름을 사용한다. 서버는 사용자 GPS를 읽지 않는다. 600m 이후 두 합성 흐름을 정지 위치에 유지하는 관측 구간을 두어 상세/잠금 화면을 검사한다. 단계 전환 버튼이나 RIDING 상태 강제 설정을 사용하지 않는다.

실행 결과는 아래에 실제 관측한 범위만 기록한다. 로컬 ActivityKit 표시를 실제 APNs 전달이나 실제 GPS 탑승 합격으로 간주하지 않는다.

지도 화면은 명시적으로 ‘오프라인 경로 시험 · 지도 타일 없음’이다. 실제 지도의 타일·실제 노선 검색·실제 서울 7016·실제 정류장 명칭을 검증한 것이 아니다. Live Activity 접근성 트리는 카드 내용을 노출하지 않아 카드 상태는 스크린샷으로 확인했다. 전체 VoiceOver 실기기 접근성 합격으로 확장하지 않는다.

재시험은 위 기기에서 내부 authenticated 합성 화면의 경로 검사 → 명시적 위치 시험 동의 → 준비 후 `scripts/qa/journey-bus-ride-replay.mjs --device 96AF9A48-4721-4335-B7BF-10B9382B7A30`로 진행했다. 차량 흐름은 합성 harness의 별도 clock이며 replay는 simctl 위치만 주입한다. 서울 API/APNs 실제 sender는 OFF다.

진단 상태 허용 목록을 최종 보완한 빌드에서도 콜드 시작→GPS 출발/ACK→차량 없는 WAITING/VEHICLE_EVIDENCE_UNAVAILABLE→BOARDING_CANDIDATE→RIDING/근거 5개와 상세 현재 버스 행을 재확인했다. 도중 창 캡처가 이전 프레임에 머물러 그 캡처는 시각적 합격 근거에서 제외했다. 같은 독립 창의 Controls→Lock 뒤 최신 19:02 잠금 프레임에서 버스 카드와 버스 구간 위치 마커를 다시 확인했다. OS의 후속 ‘항상 허용’ 선택은 변경하지 않았다.
이 최종 빌드에서도 차량 중단/GPS 30초 유지 후 19:03 잠금 카드의 ‘위치 확인 중’/위치 마커 제거와 상세 위치 없음, UNAVAILABLE/근거 0/VEHICLE_EVIDENCE_UNAVAILABLE를 확인했다. 정상 종료 후 종료 큐 0과 19:04 잠금 카드 제거도 재확인했다.
최종 종료 뒤 다시 terminate/launch한 화면은 IDLE/출발 0/근거 0/transport NOT_REQUESTED/종료 큐 0/이전 기록 없음/동의 해제였다. 시험 후 GPS 주입·시험 앱·이번 Metro 및 합성 서버를 종료했다. 시뮬레이터/앱 데이터/기존 작업 파일은 삭제하지 않았다.

## 남은 범위

- 실제 서울 7016 정류장/형상 matcher 재검증·실제 차량 입력·실기기 GPS는 미검증이다. 이번 실제 서울 API와 실제 APNs 호출은 0회이며 키/토큰을 사용하지 않았다.
- 첫 번째 버스 구간만 표시한다. R3 한 정류장 전·하차·최종 도보, R5 음성/알림, R6 지하철/환승은 아직 별도 단계다.
- 실제 공급자/도보 형상 검증이 끝나기 전에는 운영 일정에 자동 탑승을 기본 활성화하지 않는다. 앱/서버는 여전히 opt-in 개발 시험 범위다.
- 실제 APNs v2 전달·잠금 수신, 장시간·오프라인·복구와 실기기 검증은 별도 필요하다.

`.env`, 운영 설정, 사용자 데이터는 변경하지 않는다. 커밋·푸시·배포는 수행하지 않는다.

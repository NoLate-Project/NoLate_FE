# 목적지 변경 및 이동수단 전환 재현 — 부분 검증

- 날짜: 2026-09-10 KST
- 환경: 로컬 BE `127.0.0.1:5522` → 운영 MySQL (사용자 승인)
- 대상: E2E 회원 294의 개인 카테고리 161, 새 일정 338
- 제목: `E2E ETA 경로전환 0910`
- 공통 도착지: `강남역 강남역`, 주소와 좌표 없음
- 알림: 비활성. 기존 일정 333 및 공유 관계는 변경하지 않음.

## 실제 API 검증

`PUT /api/schedules/338/travel-plans/my`에 동일한 장소·좌표와 40분의 테스트 소요시간을 보내고 이동수단만 변경했다. 실제 공급자 경로 계산 검증은 아니다.

| 순서 | 이동수단 | 결과 |
| --- | --- | --- |
| 1 | TRANSIT | HTTP 400, 공통 도착지 불일치 |
| 2 | CAR | HTTP 400, 공통 도착지 불일치 |
| 3 | TRANSIT | HTTP 400, 공통 도착지 불일치 |

오류 원문: `선택한 도착지가 일정의 공통 도착지와 일치하지 않습니다.`

같은 개인 경로 API 요청에서는 자차도 목적지 검사를 우회하지 않는다. 사용자가 관찰한 화면 차이를 설명하려면 UI의 입력 상태와 최종 요청을 별도로 비교해야 한다.

## 추가로 확인된 상태 표시 오류

실패 후 `GET /api/schedules/338`은 공통 도착지 좌표가 없는 상태에서도 `travelPlanStatus: READY`를 반환했다. `myTravelPlan.id`, `travelMinutes`, `departAt`, `travelMode`, `origin`, `route`는 모두 null이고 `myTravelPlan.status`도 READY였다. 따라서 경로 준비됨 표시는 실제 경로 저장 성공의 증거가 아니다.

## 시뮬레이터 상태

기존 테스트 계정 화면을 확인했고 Metro를 로컬 BE 주소로 실행했다. 앱 새로고침 후 로그인이 풀렸으며 Computer Use 입력이 정상 반영되지 않아 경로 편집 UI 재현은 완료하지 못했다.

**판정: API에서 실패 재현. 시뮬레이터 UI E2E 및 실기기 알림 E2E는 미완료.**

테스트 일정 338은 증빙용으로 남아 있다. 이번 작업에서 운영 데이터를 삭제하지 않았다.

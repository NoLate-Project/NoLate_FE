# Xcode 27 / 빌드 54 복구 검증

## 결과

2026-09-22~23 KST에 사용자 요청으로 iOS 앱과 세 확장을 1.3.0 (54)로 통일하고 빌드 오류를 수정했다. Xcode 27.0 (27A266a), iOS Simulator 27.0 SDK에서 arm64·x86_64 Release 빌드가 종료 코드 0 / `BUILD SUCCEEDED`로 완료됐다.

## 원인과 수정

1. Pods 리소스/개인정보 번들 9개의 최소 iOS 버전이 9.0~13.4였다. 현재 SDK의 최소 허용 버전 15.0보다 낮아 Target Integrity 오류가 발생했다. `ios/Podfile`의 `post_install`에서 모든 Pods 타깃의 낮은 deployment target을 앱의 최소 버전 16.6으로 올린다. 더 높은 값은 유지한다. `pod install --no-repo-update` 후 174개 타깃/구성 조합에 16.6 미만 값이 없음을 확인했다. 라이브러리 잠금 버전은 변경하지 않았고 Podfile checksum만 갱신됐다.
2. 이 오류를 해결한 뒤 앱의 `ViewModeGlassControlManager.m`이 생성된 Swift 헤더를 통해 prebuilt React 프레임워크를 가져오는 단계에서 non-modular header 오류가 발생했다. Clang explicit modules를 끄는 비교 빌드만으로는 해결되지 않았다. 메인 NoLateFE 타깃의 Debug/Release에만 `CLANG_ALLOW_NON_MODULAR_INCLUDES_IN_FRAMEWORK_MODULES = YES`를 적용해 해결했다. Pods와 확장의 모듈 설정 및 기존 Swift explicit modules 설정은 유지했다.
3. `app.json`, Xcode의 배포 타깃 Debug/Release 8개 구성, `verify-release-config.mjs`의 기대 빌드 번호를 54로 통일했다. 비배포 테스트 타깃의 기존 52는 유지했다.

앱 기능 코드와 bundle identifier는 수정하지 않았다. CocoaPods가 재생성한 프로젝트 주석 이름과 빈 `outputPaths` 생략은 빌드 의미 변경이 아니다.

## 검증

- `ruby -c ios/Podfile`: 통과.
- `npm run verify:release-config`: 통과.
- `node scripts/verify-release-config.mjs --platform ios`: 통과.
- 변경 설정 파일의 `git diff --check`: 통과.
- 최종 빌드는 임시 헤더/모듈 설정 오버라이드 없이 저장된 프로젝트 설정만 사용했다.
- 최종 로그: `/private/tmp/nolate-xcode27-build54-final.log`.
- 결과물: `/private/tmp/nolate-xcode27-build54/Build/Products/Release-iphonesimulator/NoLateFE.app`.
- 결과물의 네 `Info.plist`를 읽어 아래 값을 검증했다.

| 타깃 | 버전 / 빌드 | 최소 iOS |
| --- | --- | --- |
| NoLateFE | 1.3.0 / 54 | 16.6 |
| NoLateShareExtension | 1.3.0 / 54 | 16.6 |
| NoLateWidget | 1.3.0 / 54 | 16.6 |
| NoLateLiveActivityExtension | 1.3.0 / 54 | 16.6 |

```sh
xcodebuild -workspace ios/NoLateFE.xcworkspace -scheme NoLateFE \
  -configuration Release -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /private/tmp/nolate-xcode27-build54 \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- build
```

빌드를 막지 않는 타사 라이브러리의 deprecated API·헤더·스크립트 경고는 남아 있다. 이번 검증은 시뮬레이터 Release 컴파일 검증이며 iOS 27 실행 동작, 실기기 Archive, App Store 업로드·심사 제출은 수행하지 않았다. 2026-09-09 보고서의 빌드 55 설정은 당시 이력이며 현재 확정 번호는 사용자 요청에 따른 54다.

참고: [Expo 공식 변경 이력](https://github.com/expo/expo/blob/main/packages/expo-modules-autolinking/CHANGELOG.md)에도 Xcode 27에서 낮은 resource bundle deployment target 보정 이슈가 기록돼 있다. 이 프로젝트에는 SDK/의존성 전체 업그레이드 대신 현재 잠금 버전을 유지하는 Podfile 보정을 적용했다.

# iOS XCUITest 자동 제어 검증 (2026-10-03)

## 환경

- Xcode 27 / iOS 27, 설치된 NoLate 1.3.0 (54) Debug 앱.
- 전용 시뮬레이터: `NoLate XCUITest 20261003`, UDID `9EFFB87E-1E6D-4C2B-A81C-2D38CCF6EC69`.
- 기존 `iPhone 18 Pro`의 로그인 세션과 별도로 실행한다. Device Hub에서 전용 기기를 선택해야 자동 조작 화면이 보인다.
- API: 기존 사용자 개발 서버 `http://127.0.0.1:5522`. 별도 서버를 띄우지 않았다.
- Metro: `http://127.0.0.1:8081`.
- 정식 회원가입 API로 생성한 합성 회원 296. 비밀번호는 저장소에 포함하지 않았다.

## 구성

`e2e/ios/NoLateE2E.xcodeproj`는 앱 프로젝트와 독립된 XCUITest 실행기다. 설치된 앱을 bundle ID로 활성화하여 입력·탭·길게 누르기와 화면 검증을 수행한다. 제품 코드나 인증 우회 기능은 추가하지 않았다. 실행법은 `e2e/ios/README.md`에 기록했다.

## 자동화 실패와 보완

- 이미 로그인된 기기에서 로그인 필드를 찾던 초기 상태 불일치: 전용 시뮬레이터로 분리.
- 첫 실행의 딥링크 시스템 확인창: XCUITest에서 `열기` 처리. 새 기기 초기화와 Metro 첫 로딩은 테스트 실행 전에 완료한다.
- 기존 입력의 커서 위치 때문에 일부 문자가 남거나, 묶음 입력에서 문자가 빠짐: 전체 선택·삭제 후 문자별 입력, 이메일·일정 제목 정확한 값 검증.
- SwiftUI glass toolbar가 XCTest 기본 탭에서 유효하지 않은 hit point를 보고: 현재 접근성 요소 프레임의 중앙을 탭하고 다음 메뉴를 검증. 초기 화면 전환 중 클릭 누락에 한해 한 번 재시도.
- 수정 후 복귀 화면 및 헤더 준비 시점: 상세 화면/달력 진입 경로를 구분하고 화면 요소 준비를 기다린다.
- UI 실행 중 같은 계정으로 별도 API 로그인한 뒤 앱 세션이 해제된 정황: 최종 UI 실행과 API 확인을 병행하지 않는다. 정확한 서버 세션 무효화 원인은 이번에 별도로 확정하지 않았다.

실패 진단 수집이 오래 남은 이전 xcodebuild 실행기 두 개는 정리했다. 원본 앱·서버는 종료하지 않았다. 합성 계정의 `XCUITest <timestamp>` 검증 일정은 화면 확인을 위해 남겨 두었다.

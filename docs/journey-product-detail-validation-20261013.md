# 제품 경로 상세 연결 검증 — 2026-10-13

## 범위와 판정

- 기존 길안내 진입은 수동 출발 화면 대신 일정 경로 상세로 연결한다. 양쪽 개발 게이트가 켜진 iOS에서만 동작한다. 잘못된 일정 ID·중복 배열·Android·release는 차단한다.
- 실제 `ScheduleDetail` 렌더러에 5구간 합성 일정과 고정 loopback 시험 인증을 주입했다. 일반 로그인/실사용 일정/운영 서버를 통과한 E2E는 아니다.
- `NoLate Mixed Journey E2E 20261012` 독립 기기 창에서만 조작했다. 창 도구 모음의 `Show in Device Hub`를 확인했다. 실기기는 사용하지 않았다.
- GPS는 `simctl location`으로 공급한 합성 좌표다. 차량은 승객 GPS를 받지 않는 별도 시계의 합성 공급자다. 단계 전환 명령이나 탑승·하차 버튼은 사용하지 않았다.
- 지도는 타일 없는 QA 렌더러다. 실제 TMAP 지도 타일/외부 API/이번 버전의 실제 APNs 검증을 대신하지 않는다.

## 구현

1. `JourneyGuidanceScreen`은 엄격히 검증한 일정 ID로 경로 상세에 redirect한다. 수동 시작 hook을 호출하지 않는다.
2. 기존 출발 요약 때문에 현재 안내 막대가 접힌 시트 아래로 밀리는 결함을 수정했다. 검증된 자동 안내 binding이 있을 때 출발 hero를 숨기고 현재 단계/막대를 표시한다. 준비되지 않은 일정의 요약은 유지한다.
3. 환승 대기 막대의 현재 노선을 첫 버스로 고정하던 범례를 다음 BUS occurrence로 수정했다.
4. GPS replay에 선택적인 60초 환승 정류장 체류를 추가했다. 승객 위치와 EMPTY 공급자만 입력하며 두 번째 차량 시계를 별도로 시작한다. 제품 판정 임계값은 바꾸지 않았다.
5. 실제 상세 지도 controller와 타일 없는 QA 지도에 서버 소유 도보 형상을 별도로 연결했다.
   현재 in-memory armed input에 정확히 매칭된 AUTHENTICATED binding만 사용한다.
   소유자/login/일정/revision/generation·원래 admission 시각·navigation deadline·형상 연결을 검사하고
   저장 ODsay 구간·원본 evidence를 수정하거나 TMAP을 ODsay로 재명명하지 않는다.
   지도 bounds·도보 구간 카메라도 별도 형상을 사용하며 버스 overlay는 유지한다.
   GPS가 불확실할 때 정적인 유효 경로선은 남지만 현재 위치 마커는 기존 15초 정책대로 숨긴다.

## 증거와 남은 조건

화면 자료: `docs/evidence/journey-product-detail-20261013/`.

운영 DB 실제 마이그레이션은 별도의 [적용 기록](journey-production-migration-20261013.md)을 따른다.

후속 APNs 준비로 test-source 실전송 client에 단일 설치 digest/UPDATE 최대 80·END 최대 2/
monotonic 20분 상한을 연결했고 **새 회귀 3 PASS**를 확인했다. START는 거절하고 실패도
시도 예산을 소비한다. 이는 프로세스 한 번의 상한이며 재실행 승인이나 외부 전송 성공을
뜻하지 않는다. 이번 15546 다중 도보 harness는 여전히 realProvider=false이며 새 APNs
통합/전송은 하지 않았다. 별도 승인을 요청한 상태다.

전체 제품 완료에는 실제 로그인 상세 진입, 일반 지도 타일의 도보 overlay 시각 검사, 장시간 수명,
지하철 공식 catalog와 승객 결합, 접근성/음성·무음 정책, 신규 실제 APNs 표시와 현장 GPS 검증이 남아 있다.

# NoLate 실제 대중교통 길안내 — 실행 로드맵

기준: 2026-10-20. [현재 상태·증거](journey-navigation-status-20261012.md)가 단일 완료 판정표다.
이 문서는 앞으로 할 일만 관리한다. 과거의 상태·설계는
[이전 로드맵](journey-guidance-roadmap-history-through-20261013.md)에 보존한다.

## 목표와 변경하지 않을 요구사항

- 안내 동의/종료/채널 설정은 사용자 제어로 남긴다. 출발·탑승·하차·환승은 버튼으로 처리하지 않는다.
- GPS와 독립 교통 관측을 결합해 현재 구간과 구간 안의 위치를 판단한다. 열차/차량 위치만으로 승객 위치를 확정하지 않는다.
- 상세 지도·경로 바·목록과 Live Activity는 같은 상태를 표시한다. 퍼센트 대신 “구로역까지 도보 100m”, “다음 정류장 하차”, “열차 약 2분 뒤 도착”처럼 근거 있는 현재 단계/다음 행동을 표시한다.
- 한 정류장 전/접근 안내, 환승·대기시간, 음성·알림과 잠금 상태를 지원한다. 공개 API의 무음 제약은 명시적 채널 설정과 실기기 검증으로 다룬다.
- 정보가 끊기면 불확실 상태로 전환한다. 경로 이탈/잘못된 탑승/지나침을 복구한다.
- 전국/모든 노선 지원, 실제 GPS 정확도, 무음/배터리 안정성은 현재 확보했다고 가정하지 않는다.

## 반복 작업을 막는 실행 규칙

1. **동시에 진행하는 핵심 작업은 아래 한 항목뿐이다.** 선행 조건이 막히면 원인과 필요한 입력을 기록한다. 무관한 진단 화면/보강 테스트를 다음 단계로 만들지 않는다.
2. 진행 보고에는 사용자에게 새로 가능해진 동작, 실제 소비 코드, 검사 범위, 미완료 조건을 적는다. 테스트 개수·문서 개수·하위 단계 번호로 완료를 판단하지 않는다.
3. 각 작업은 구현→관련 자동 검사→독립 시뮬레이터의 실제 소비 화면 확인을 끝내야 닫는다. UI가 없는 계약은 계약 검사로만 표시한다.
4. **합성 공급자/주입 GPS, 실제 공급자 응답, 실제 APNs, 실기기 현장 검증은 서로 대체하지 않는다.** 과거 다른 계약의 APNs 성공을 최신 계약에 전용하지 않는다.
5. 이미 완료한 DB migration/기존 성공 시나리오는 관련 변경이나 실패가 있을 때만 재검증한다. 새 승인을 이전 작업의 재실행 사유로 삼지 않는다.
6. 출시 차단 결함은 해당 핵심 작업 안에서 수정한다. 핵심 의존성을 해결할 수 없으면 안전한 상태로 멈추고 정확한 차단 요인을 보고한다. 우회 작업으로 무한 진행하지 않는다.
7. 새로운 결과는 [현재 상태](journey-navigation-status-20261012.md)의 해당 행을 **갱신**한다. “최신” 절을 계속 덧붙이지 않는다. 실패 로그·화면·백업은 보존한다.

Android 동등 기능은 이 iOS 경로가 닫힌 뒤의 후속 범위다.

## 현재 선행 의존성의 정확한 경계

키는 조회 자격이지 역 대응/운행 계통 자료가 아니다. ODsay는 [공식 답변](https://lab.odsay.com/community/boardView?seq=699)에서
길찾기 지하철역 ID가 내부용이며 외부 공공 API의 역 코드로 사용할 수 없다고 명시했다.
공개 API만으로 두 ID를 등치할 수 없고, 이름·좌표의 자동 대응도 제품 판정 근거로 쓰지 않는다.
2026-10-13 서버 환경의 현재 iOS 키로 `subwayStationInfo`를 호출했을 때 `ApiKeyAuthFailed`가 반환됐다.
키 형식·플랫폼 허용 범위·등록 상태는 공급자 콘솔에서 별도 확인이 필요하다.

대안으로 [서울교통공사 최단경로이동정보](https://www.data.go.kr/data/15143842/openapi.do)는
출발/도착역 간 정차역·환승/소요시간을 제공한다. 공개 Swagger 계약은
`getShtrmPath2`, `body.paths[].dptreStn/arvlStn.stnCd`, 종착역·방면 필드를 명시한다.
2026-10-13 `NoLate_BE/env.local.properties`에 등록된 키로 공식 HTTPS API를 실제 조회했다.
강남→역삼은 `0222→0221`, 강남→서울역은 2호선 사당 `0226`→4호선 사당 `0433`의
명시적 환승을 포함한 12개 구간을 반환했다. 응답 성공 코드는 문자열 `"00"`이며 역 코드는
앞자리 0을 보존해야 한다. 서버 파서와 실서비스 opt-in 계약 검사를 이 응답에 맞춰 통과시켰다.
저장된 ODsay 구간의 **모든 역명·노선·순서**와 공식 경로를 대조하는 후보 검증기를 추가했다.
서울시 일괄 도착 API의 `(호선, 역명, statnId)`가 유일하고 공식 경로 코드 끝자리도
일치할 때만 일회성 역 대응 후보를 만들도록 했다. 이는 숫자 패턴만으로 자동 변환하는
기본 OFF의 on-demand catalog 후보로 연결했다. [서울교통공사 공식 1~8호선 역 좌표 CSV](https://www.data.go.kr/data/15099316/fileData.do)의
호선·외부역코드·역명과 저장 좌표도 350m 이내에서 대조하며 파일이 없거나 달라지면 차단한다.
350m는 파일 대조의 임시 허용치로 현장/역사별 검증 전에는 제품 승격 기준이 아니다.
이는 역사 대표점 검증이지 승객 위치 판정이 아니다. 실제 일괄 도착 응답 `INFO-000` 2,994행과 다음 조회 2,983행에서
강남·역삼 및 2/4호선 사당의 후보 대응을 검증했다. 강남→선릉 저장 fixture는 공식 구간·성수 종착역까지의 전체 정차 순서와 방면을 대조했다.
실제 사용자 저장 경로·승객 판단·제품 경로/시뮬레이터 E2E는 아직 미검증이다.
공식 경로의 역 코드는 열차 위치의 `statnId`와 **동일 문자열이 아니다**.
예를 들어 역삼 2호선의 공식 경로 코드는 `0221`, 실시간 위치 ID는 `1002000221`이다.
한 저장 구간의 전체 역명·호선·정차 순서와 일괄 도착 피드의 유일한 역 ID를
동시에 대조하는 보수적 후보만 만든다. 번호 접미부만으로 ID를 변환하거나
다른 노선·분기·급행으로 일반화하지 않는다. 실제 사용자의 저장 경로·역 좌표·
GPS/열차 연속성 확인 전에는 기존 ODsay 구간을 제품에서 임의로 치환하지 않는다.
서울 실시간 열차 `realtimePosition`은
2호선 실제 HTTP 응답(INFO-000, 45행, 2026-10-13)을 한 번 확인했다. 공식 HTTPS 호스트
호출은 제한 시간 내 응답하지 않았고, 현재 서버는 평문 HTTP를 운영 기본값에서 거부한다.
실제 연결 전에 HTTPS 중계 또는 명시적 HTTP 위험 수용 결정을 해야 한다.

서버 소유 검토 JSON을 읽는 `journey.subway-observation.catalog-file` loader도 연결했지만
검토 파일은 설치하지 않았다. 새 on-demand catalog는 명시적 opt-in이며,
지원하지 않는 경로는 빈 결과로 차단한다. 역명 또는 가까운 좌표만으로 열차에 탑승했다고
추측하지 않는다.
ODsay 공개 계약 검토와 현재 코드의 근거는
[지하철 연결 검증 기록](journey-owned-subway-observation-validation-20261013.md)의 “남은 제품 연결”을 따른다.
공급자의 별도 자료가 존재하지 않는다고 단정하지 않는다. 필요한 것은 실제 대응 자료 또는
두 공급자의 공통 식별자/정차 순서를 증명하는 공식 계약이며, 개인 키 원문을 채팅으로 받을 필요는 없다.
ODsay 공식 [subwayStationInfo 계약](https://lab.odsay.com/guide/releaseReference?platform=web)의
이전/다음 역 ID·좌표를 연결 근거 후보로 검토했다. 이것만으로 서울 STATN_ID나 종착/급행
계통이 증명되지는 않으므로 실제 응답 대조 전에 catalog 설치나 제품 진입을 허용하지 않는다.

다음 작업은 **실제 사용자 저장 지하철 구간과 신선한 열차 응답을 native GPS 판단·
독립 시뮬레이터 상세/잠금 화면까지 대조**하는 것이다. 출처 없는 매핑이나
합성 fixture를 운영 자료로 설치하지 않는다.

## 운영 및 검증 원칙

운영 DB 5개 migration은 이미 완료했다. 재실행하지 않는다.
운영 서버 재기동/배포/기본 ON과 실제 외부 전송·실기기 조작은 각각의 작업 범위와 안전 조건을 확인한다.
`.env`/키/기존 사용자 데이터/백업은 보존한다. 시뮬레이터는 지정된 **독립 창**만 사용한다.
[실기기 검증 runbook](journey-device-validation-runbook.md)을 인계 절차로 유지한다.

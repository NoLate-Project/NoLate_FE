# R2 버스 탑승·주행 판정 코어 — 2026-10-07

## 상태

**순수 판정 코어의 첫 slice만 구현했다. R2 전체/R3–R6 완료 기록이 아니다.**
실제 공급자→native Runtime→정상 경로 상세/Activity 연결은 아직 없다.
실제 7016 자동 탑승이나 완주를 합격 처리하지 않는다.

## 구현

`NoLateJourneyBusRideCore`는 네트워크/위치 관리자/UI와 분리된 in-memory Swift reducer다.
기존 자동 출발·정류장 접근 코어를 교체하거나 수동 단계 전환을 추가하지 않았다.

- 같은 session/generation/revision/epoch·경로·수명의 접근 코어 snapshot을 요구한다.
  연속 정류장 대기와 이동을 만족한 `BOARDING_CANDIDATE`부터 차량 동행을 검사한다.
- 동일 노선 ID·방면, 검증된 WGS84 좌표 출처, 원본 관측 시각 기준 최대 15초를 요구한다.
  `.syntheticReplay` 입력을 실제 제공처 출처로 승격하지 않는다.
- 차량의 **원본 관측 시각**에 맞는 과거 GPS 위치를 비교한다. 두 GPS 사이가 8초 이하일 때만
  경로상 위치를 보간하며 미래/지하 단절을 외삽하지 않는다. 서로 다른 시각의 좌표를 같은 순간처럼 비교하지 않는다.
- 같은 차량의 서로 다른 원본 fix가 3개 이상, 12초 이상, 70m 이상 동행해야 `RIDING` 후보 근거가 성립한다.
  수신 시각만 바뀐 같은 fix는 증거 수와 TTL을 늘리지 않는다.
- 후보가 둘 이상이면 임의로 가까운 버스를 선택하지 않는다. 중복 ID 행도 후보에서 제외한다.
  차량이 바뀌면 이전 증거를 넘겨주지 않는다. 속도만 빠르거나 대기 이력이 없으면 확정하지 않는다.
- 부정확/만료/역순/점프 GPS, 만료 차량, 역방향 이동, 15초 만료에서는 정밀 위치·탑승 확정을 제거한다.
  `tick`은 만료만 처리하고 위치를 앞으로 움직이지 않는다. 종료/10분 이내 세션 만료는 terminal이다.
- 차량 ID·GPS 이력은 메모리에만 있으며 Codable/HTTP/Activity/진단 payload로 내보내지 않는다.
  이 코어에는 저장/복원 API가 없다. 과거 탑승 확정을 복원하려면 별도 재검증 계약이 필요하다.

현재 임계값은 버전 관리된 개발 초기 정책이며 현장 정확도 인증값이 아니다.
특히 같은 도로에서 다른 이동수단이 버스와 함께 이동하는 상황은 현장 negative trace로 검증해야 한다.
상위 정규화 경로의 geometry/정류장 occurrence 검증과 실제 provider identity·방면 검증이 선행 조건이다.
생성자의 입력 타입/출처 라벨만으로 실제 경로가 검증됐다고 주장하지 않는다.
